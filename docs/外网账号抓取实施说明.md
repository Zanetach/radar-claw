# 外网账号抓取实施说明

本实现提供一个独立 Python 采集模块，支持 no-token 和 API token 两种采集模式，将外网账号内容元数据写入 SQLite。默认不下载图片、视频或其它媒体文件。

## 文件结构

- `crawler/`：采集程序、Excel 导入、数据库 schema、平台 API provider。
- `tests/`：解析、去重、门槛判断测试。
- `requirements.txt`：运行 Excel 导入所需依赖。

## 初始化

```bash
python3 -m pip install -r requirements.txt
python3 -m crawler --db data/radar_sources.sqlite3 init-db
python3 -m crawler --db data/radar_sources.sqlite3 import-accounts --excel 外网抓取账号0424.xlsx
```

也可以直接启动API/CLI，首次启动会在数据库为空时自动导入 Excel：

```bash
python3 -m crawler.web --db data/radar_sources.sqlite3 --excel 外网抓取账号0424.xlsx --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765` 后可管理账号源、配置 handle/channelId/URL、启停账号、触发采集、查看内容候选和异常记录。

Excel 中的多平台账号会拆成多个 `source_accounts` 记录，例如 `X/YouTube-Alex Hormozi` 会生成 `x` 和 `youtube` 两条源账号。第 33 行 `X/Instagram-Grant Cardone` 会记录数据质量问题，因为账号平台字段与阅读量字段存在 Instagram/YouTube 不一致。

## 采集模式

支持三种模式：

```bash
python3 -m crawler --db data/radar_sources.sqlite3 crawl --mode auto
python3 -m crawler --db data/radar_sources.sqlite3 crawl --mode no-token
python3 -m crawler --db data/radar_sources.sqlite3 crawl --mode api
python3 -m crawler --db data/radar_sources.sqlite3 crawl --mode browser-session
python3 -m crawler --db data/radar_sources.sqlite3 crawl --mode chrome-session
```

- `auto`：默认模式，按平台策略选择 provider：
  - X：`xmcp -> api -> chrome-session -> x-rss`
  - YouTube：`no-token -> api`
  - LinkedIn：`api`
  - Instagram：`api`
- `no-token`：不使用任何 token。当前 YouTube 支持公开 RSS feed；X、LinkedIn、Instagram 没有稳定官方免 token 元数据 feed，会写入 `crawl_failures.no_token_unavailable`。
- `api`：只使用官方 API token，适合正式采集阅读量、互动数等指标。
- `xmcp`：通过 X MCP 调用官方 X API 工具，适合生产主路径；如果 X credits 不足，会返回 `credits_depleted`。
- `browser-session`：复用 Chrome 登录态，通过 WebBridge 抓取。当前实现支持 X 账号主页可见帖子，不自动登录、不处理验证码、不绕过风控。
- `chrome-session`：`browser-session` 的产品化别名，推荐在 Agent 指令、MCP 参数和 Hermes Agent 中使用这个模式名。
- `x-rss`：通过 xgo.ing/BestBlogs RSS 抓取 X 文本和图片，适合免费兜底；不保证视频和完整指标。

## Browser Session 模式

这个模式借鉴 `autoclaw-cc/x-cli` 的 WebBridge 架构，但直接集成在 Python 后端中，不需要 Go。Go 只在你要单独构建外部 CLI 二进制时才需要。

前置条件：

1. 启动本地 Chrome WebBridge：

```bash
./tools/run_chrome_webbridge.sh
```

2. 脚本会启动一个带 CDP 调试端口的独立 Chrome Profile，并打开 `https://x.com/home`。
3. 在这个 Chrome 窗口中手动登录 X。
4. 在API/CLI账号源里补充 X 账号的 `account_handle`，例如 `elonmusk`。

检查状态：

```bash
curl http://127.0.0.1:10086/status
```

运行 X chrome-session 采集：

```bash
python3 -m crawler --db data/radar_sources.sqlite3 crawl --platform x --mode chrome-session --limit 1 --max-results 5 --allow-failures
```

如果 WebBridge 未运行，会记录 `webbridge_unavailable`；如果 Chrome 未登录 X，会记录 `not_logged_in`；如果遇到验证码，会记录 `captcha_required`。

## API 凭证

按需配置环境变量：

```bash
export X_BEARER_TOKEN="..."
export YOUTUBE_API_KEY="..."
export LINKEDIN_ACCESS_TOKEN="..."
export INSTAGRAM_ACCESS_TOKEN="..."
```

YouTube API 和 RSS 都需要在 `source_accounts.account_handle` 中补充 `channelId`，也可以在 `source_accounts.account_url` 中保存 `https://www.youtube.com/channel/<channelId>`。LinkedIn 需要授权 author URN。Instagram 需要授权 Business/Creator user id。缺少这些授权标识时，采集器会写入 `crawl_failures`，不会尝试页面爬虫。

## 运行采集

```bash
python3 -m crawler --db data/radar_sources.sqlite3 crawl --platform youtube --mode no-token --limit 2 --max-results 20 --allow-failures
python3 -m crawler --db data/radar_sources.sqlite3 crawl --platform x --mode api --limit 2 --max-results 20 --allow-failures
```

采集结果写入：

- `source_accounts`：外网账号源，含分类、平台、门槛、Radar 号信息、游标和最近状态。
- `source_contents`：统一内容元数据，含原始内容 ID、标题/正文、链接、发布时间、阅读/点赞/评论/转发、达标状态。
- `crawl_failures`：限流、缺少授权、账号不存在、网络错误等失败记录。

## 达标判断

- `qualified`：阅读量达到门槛，且互动率达到门槛。
- `below_threshold`：已获得指标但低于门槛。
- `metrics_pending`：阅读量或互动指标缺失，不直接判定不合格。

## 当前边界

- 不绕过登录、不模拟用户、不抓网页 DOM。
- YouTube 可通过 RSS 在 no-token 模式获取标题、链接、发布时间，但不会有播放量、点赞、评论。
- X 和 YouTube 可通过 API 模式获取更完整指标。
- LinkedIn 和 Instagram 仅支持官方授权可访问的账号，不保证能抓取普通个人公开账号。
